# PHASER DDR3 open-source bring-up status

## Goal

Deliver a PHASER-based, open-built x8 DDR3 path for YPCB, ending in a usable host-side driver.

Final success means:

- RTL builds through the open flow: Yosys -> nextpnr/OpenXC7 -> FASM -> frames -> bitstream.
- The bitstream uses PHASER hard macros, not the current no-PHASER rowstream fallback.
- Hardware bring-up is repeatable across program cycles.
- A host driver can perform low-byte and full-beat DDR3 reads/writes through the PHASER shell and pass integrity checks.

The no-PHASER rowstream/BIST path remains useful only as a regression oracle for board access, JTAG transport, and host UX shape.

## Autonomous PHASER workflow and board lock

PHASER work in this repository continues autonomously from `origin/main`.
The manual vanilla UberDDR3 clone is a separate track and must not be read,
modified, built, programmed, or otherwise used by this workflow.

Builds and static analysis do not require exclusive board access. Any PHASER
hardware validation that programs the FPGA or performs JTAG readback through
OpenOCD/openFPGALoader must first acquire the shared HS3 lock:

- `/tmp/ypcb-hs3-210299BF3824.lock`

Use `scripts/task6/task6_board_run.py with-lock` for board-facing commands so
OpenOCD programming and JTAG status reads serialize with manual vanilla tests
on HS3 serial `210299BF3824`.

6. Classify each remaining focused delta as required feature, conflicting

7. Patch only classified, oracle-backed rows/exclusions and gate each candidate
   with three consecutive OpenXC7 program/read cycles.
